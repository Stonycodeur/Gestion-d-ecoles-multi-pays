# Intégrations externes

Chaque service a un adaptateur **sandbox** (par défaut, aucune clé) et un adaptateur **live**, choisis par variable d'environnement.

| Service | Variable de mode | Variables live | Mise en production |
|---|---|---|---|
| Stockage | `STORAGE_MODE` (`sandbox` = disque, `live` = S3/MinIO) | `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_REGION` ; sandbox : `STORAGE_DIR` | Créer le bucket MinIO/S3 privé, jamais public |
| Push (Android + iOS) | `PUSH_MODE` | `FCM_SERVICE_ACCOUNT_JSON` (compte de service Firebase) | 1) Créer un projet Firebase. 2) Ajouter les apps Android et iOS avec l'identifiant définitif. 3) Mettre `google-services.json` / `GoogleService-Info.plist` dans `apps/mobile` (ignorés par git). 4) iOS : créer une clé APNs (.p8) dans Apple Developer et la téléverser dans Firebase > Cloud Messaging. 5) Activer la capacité Push Notifications dans Xcode. |
| TimescaleDB (série des positions GPS) | automatique si l'extension `timescaledb` est installée dans la base (image `timescale/timescaledb:latest-pg16` en développement) | aucune ; sur une base gérée : `CREATE EXTENSION timescaledb;` une fois, puis `SELECT provision_tenant_schema('<école>')` pour chaque école existante | `gps_positions` devient une hypertable (chunks d'un jour, clé `(id, recorded_at)`) ; RLS forcé et purge par durée de conservation inchangés (DELETE). Sans l'extension : table PostgreSQL ordinaire, même comportement. Pas de compression ni de rétention native Timescale (incompatibles avec la durée configurable par établissement). Testé en CI avec et sans l'extension. |
| RabbitMQ (envoi asynchrone des SMS et e-mails) | `QUEUE_MODE=rabbitmq` (défaut : `inline`, envoi immédiat dans le processus) | `RABBITMQ_URL`, `RABBITMQ_RETRY_MS` (10000), `RABBITMQ_MAX_ATTEMPTS` (3) | File durable `outbound.messages` ; un envoi en échec est repris après le délai, puis déposé dans `outbound.messages.dead` après la dernière tentative (à surveiller et rejouer par l'exploitation). Broker injoignable à la publication : envoi direct unique. Consommateur : reconnexion automatique toutes les 5 s. Testé contre un vrai RabbitMQ en CI. Les push, notifications internes et webhooks ne passent pas par la file. |
| Elasticsearch (recherche des ressources pédagogiques) | `SEARCH_MODE=elasticsearch` (défaut : PostgreSQL) | `ELASTICSEARCH_URL`, `ELASTICSEARCH_API_KEY` (optionnel), `ELASTICSEARCH_TIMEOUT_MS` (2500) | Un index par établissement (`em-<école>-resources`, analyseur français sans accents). PostgreSQL reste la source de vérité et applique filtres et droits ; Elasticsearch ne fait que classer. Indexation à la création/report ; `POST /resources/reindex` (administration) reconstruit l'index. Panne : repli automatique sur PostgreSQL. Testé contre un vrai Elasticsearch 8 en CI. Les séances du cahier de textes restent sur la recherche PostgreSQL. |
| Redis (limites de débit et quotas de l'API publique partagés entre réplicas) | `REDIS_URL` (absent : compteurs en mémoire, par réplica) | `REDIS_URL` | Compteurs à fenêtre fixe atomiques (script Lua). Si Redis est injoignable, l'API compte localement et continue (journalisé une fois). Testé contre un vrai Redis en CI. Redis n'est pas utilisé pour le cache ni les sessions. |
| SMS | `SMS_MODE` | `TWILIO_SID`, `TWILIO_TOKEN`, `TWILIO_FROM` | Compte Twilio ou passerelle locale à brancher sur l'interface `SmsAdapter` |
| E-mail | `EMAIL_MODE` | `SMTP_URL` (ex. `smtps://user:pass@host`), `EMAIL_FROM` | Domaine d'envoi avec SPF/DKIM |
| Messagerie | — | `MESSAGE_KEY` (base64, 32 octets : `openssl rand -base64 32`) | Générer une clé par environnement, la stocker dans un gestionnaire de secrets, prévoir la rotation |
| Temps réel | — | `CORS_ORIGINS` (liste séparée par des virgules) | Origines web autorisées |

En mode sandbox, les push sont écrits dans la table `push_outbox` (consultable via `GET /push-outbox`), les SMS/e-mails sont conservés en mémoire : mêmes flux que le réel.

| IA prédictive | `AI_MODE` (`sandbox` = modèle JSON en processus, `live` = service FastAPI) | `AI_SERVICE_URL`, `AI_SERVICE_KEY` ; sandbox : `AI_MODEL_PATH` | Entraîner avec `python apps/ai/train.py` sur des données réelles anonymisées, relire `MODEL_CARD.md` et la mesure de biais avant d'activer ; xgboost/shap optionnels (`requirements.txt`) |

| Paiement (tous prestataires) | `PAYMENT_MODE` (`sandbox` par défaut, `live`) | `PAYMENT_WEBHOOK_SECRET` (≥ 16 caractères, sert aussi à signer le QR espèces), `PAYMENT_RETURN_URL` | Sandbox : le même flux que le réel (demande → webhook signé → reçu) ; `POST /payments/:id/sandbox-confirm` joue le rôle de l'opérateur et est désactivé en `live` |
| Carte (Stripe) | `PAYMENT_MODE=live` | `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | Webhook : `POST /payments/webhooks/stripe/<slug-etablissement>` (événement `checkout.session.completed`) |
| Airtel Money | `PAYMENT_MODE=live` | `AIRTEL_BASE_URL`, `AIRTEL_CLIENT_ID`, `AIRTEL_CLIENT_SECRET`, `AIRTEL_CALLBACK_SECRET` | Callback : `POST /payments/webhooks/airtel_money/<slug>` signé (HMAC) ; **adaptateur écrit d'après l'API publique Airtel, non testé en réel : à valider avec le compte marchand** |
| Moov Money | `PAYMENT_MODE=live` | `MOOV_BASE_URL`, `MOOV_API_KEY`, `MOOV_CALLBACK_SECRET` | Callback : `POST /payments/webhooks/moov_money/<slug>` ; **format générique : à aligner sur la documentation remise par Moov à l'ouverture du compte marchand** |
| GPS (chiffrement) | — | `GPS_KEY` (base64, 32 octets : `openssl rand -base64 32`) | Obligatoire pour enregistrer/lire des positions ; ne jamais le commiter |
| GPS (carte mobile) | `--dart-define=MAP_TILE_URL=...` | URL de tuiles | Défaut : tuiles OpenStreetMap (usage modéré) ; en production, utiliser un fournisseur de tuiles contractuel ; le web utilise l'intégration OpenStreetMap |

| Ministères | `MINISTRY_MODE` (`sandbox` par défaut, `live`) | `MINISTRY_<CODE_PAYS>_URL`, `MINISTRY_<CODE_PAYS>_TOKEN` ; sandbox : `MINISTRY_SANDBOX_FAIL_FIRST=n` pour simuler n échecs | Les connecteurs (API ou fichier CSV/XML/JSON) sont dans `countries.ministry_connectors` ; en production, aligner le format de l'adaptateur HTTP sur la documentation du ministère |
| API publique | — | `API_TOKEN_SECRET` (≥ 32 caractères ; sinon `SANDBOX_JWT_SECRET`) | Clients créés par l'établissement (secret montré une fois) ; `POST /oauth/token` |
| Webhooks sortants | — | `WEBHOOK_KEY` (base64, 32 octets) chiffre les secrets de signature ; `WEBHOOK_ALLOW_PRIVATE` réservé aux tests | Signature `x-em-signature` = HMAC-SHA256(secret, `timestamp.corps`) |
| Marketplace | — | aucune | Publication réservée au Super-Admin racine ; pour une exécution de code tiers non fiable, isoler dans un conteneur |


| IA générative | `LLM_MODE` (`sandbox` par défaut, `live`) | `LLM_URL` (endpoint chat-completions compatible OpenAI), `LLM_API_KEY`, `LLM_MODEL` | Seuls des textes pseudonymisés quittent le serveur ; vérifier le contrat avec le fournisseur (hébergement, conservation) |
| VR/AR | — | aucune | Déposer les fichiers glb/usdz/jpg dans le stockage objet (MinIO/S3) et enregistrer leur adresse https ; poids max 25 Mo (3D) / 15 Mo (360°) |

| Keycloak / OIDC | `AUTH_MODE=oidc` (`sandbox` en développement) | `OIDC_ISSUER`, `OIDC_JWKS_URI`, `OIDC_AUDIENCE` (`ecolemanager-api`), `OIDC_WEB_CLIENT_ID`, `OIDC_MOBILE_CLIENT_ID`, `OIDC_MOBILE_REDIRECT_URI` | Importer `infra/keycloak/realm-ecolemanager.json` (clients publics PKCE `ecolemanager-web` et `ecolemanager-mobile`, mappeurs `roles`, `tenant`, `class_ids`, `child_ids`, `student_id`) ; adapter les URI de redirection au domaine réel ; en production activer TLS (`sslRequired`) ; l'émetteur vu par le navigateur et par l'API doit être identique (`KC_HOSTNAME`). Comptes démo : `npm run seed:keycloak` |
| Keycloak (désactivation à la suppression de compte) | `IDENTITY_MODE=live` (`sandbox` par défaut) | `KC_URL`, `KC_REALM`, `KC_ADMIN_CLIENT_ID`, `KC_ADMIN_CLIENT_SECRET` | Créer dans le realm un client confidentiel avec « Service accounts enabled » et lui donner le rôle `realm-management › manage-users`. À la suppression d'un compte adulte ou à l'effacement d'un élève, l'API désactive l'utilisateur Keycloak (`enabled:false`) et ferme ses sessions **avant** d'effacer les données ; si Keycloak est injoignable, rien n'est effacé (erreur 502, à répéter) et l'échec est journalisé (`account.identity_disable_failed`). L'identifiant utilisé est le `sub` du jeton. |
| Métriques | — | `METRICS_TOKEN` (≥ 16 car.), même valeur dans `infra/metrics_token` pour Prometheus | `/metrics` absent sans jeton |
| Sentry | — | `SENTRY_DSN` | Facultatif ; erreurs 5xx uniquement |
| Planificateur | `SCHEDULER=on|off` | `SCHEDULER_INTERVAL_MIN` (15) | Activé par défaut en production |
| Mobile OIDC | — | `OIDC_REDIRECT_SCHEME` (défaut `com.ecolemanager.pro`) pour `configure_native.py` | Doit correspondre à l'URI de redirection du client `ecolemanager-mobile` |
